# 老师选做范围与 3.4.0 实验接入

调查与源码核查：2026-10-19。用户授权将可独立移除的候选先集成测试。结论：最容易复用现有 NCNN 链路的是坑洞/裂缝、常见车辆、交通标志、车牌定位、限定类别垃圾。行为判断需要跟踪、固定观察区域和时间；设施损坏、事故及物理量不能由通用检测框直接推断。

## 本版可以实际试什么

保留 COCO Nano/Small、RDD2022 Nano/Small，新增六个检测器，合计十个；一次只加载所选检测器。车牌文字识别在拍照时追加一次 CPU 推理，不连续占用实时链路。

| App 模型入口 | 现成轮子 | 适用内容与限制 |
|---|---|---|
| 道路 Nano | [BDD100K YOLOv8n](https://huggingface.co/dronefreak/bdd100k-yolov8n) | 人、骑行者、六类车辆、交通灯、交通标志；标志只是通用类别，不读标志内容 |
| 标志36类 | [Traffic-Sign-Detection-YOLOv8](https://huggingface.co/ankitjha07/Traffic-Sign-Detection-YOLOv8) | 限速、禁行、停车、让行等36类；训练类别以模型自身字典为准，非中国全部标志，甚至没有限速40类 |
| 标志21类 | [traffic-sign-yolov8](https://huggingface.co/yahyagul/traffic-sign-yolov8) | 21类标志/红黄绿灯等，供对照；不能据此判断信号灯相位与具体车道的关系 |
| 车牌 + OCR | [YOLOv8n 车牌](https://huggingface.co/joker5914/yolov8n-license-plate) + [HyperLPR3](https://github.com/szad670401/HyperLPR) | 实时定位车牌，拍照后读取中文牌号候选；无四角矫正、双层牌拼接，非完整 HyperLPR SDK，侧斜/模糊牌不保证 |
| 垃圾6类 | [yolov8s-garbage-detection](https://huggingface.co/ShihoAI/yolov8s-garbage-detection) | 生物垃圾、纸板、金属、纸、塑料、其他；模型卡自报 mAP50 0.3942，类别粗，需实测 |
| 遗留物9类 | [TACO YOLO11s](https://huggingface.co/fabiocigaina/TACO-yolo11s) | 袋/包装、烟头、瓶、瓶盖、罐、其他塑料、纸盒、杯、其他；模型卡自报 mAP50 0.311，原训练尺寸896，手机320输入可能漏小目标 |

所有新增检测器已导出 NCNN 原始 DFL 输出并使用模型内类别表，避免把交通标志/车牌误按 COCO 类别显示。来源提交、权重哈希、类别和转换产物哈希见 `experiment-models-manifest.json`。YOLO11 仍使用可兼容的检测头，已经通过本地转换和加载检查。

OCR 复用官方 ONNX 识别模型转 NCNN，保留 Apache-2.0 许可；官方字典77符号而模型输出78列，未知索引77被拒绝，不猜字、不移动索引。照片和原 JSON 保存候选、置信度、格式检查及实验标志。格式通过也不等于号码正确。

## 按老师范围逐项判断

| 选做项 | 实现难度与当前处理 |
|---|---|
| 坑槽、裂缝 | 已有 RDD2022 四类：纵裂、横裂、龟裂、坑洞，可直接测试 |
| 脱落、鼓包、塌陷 | 当前 RDD 不包含这些标签；需专用标注和权重，单目鼓包/塌陷还涉及几何与阴影歧义，本版未实现 |
| 路面积水 | 找到 [Puddle-detection-model](https://huggingface.co/Ayush0000002/Puddle-detection-model)，实际权重为单类 YOLOv8；仓库无 README/许可，暂不随 APK 再分发。技术链路接近现有导出，授权明确后再接入 |
| 护栏、路灯、灯杆、指示牌损坏 | 检出设施存在不等于损坏；本次未核验到同时具备可下载轻量权重、明确类别和许可的直接替换方案。断裂、倾倒、灯不亮需分别定义，路灯不亮还需昼夜条件 |
| 树木遮挡指示牌 | 标志被完全挡住时检测不到；仅树框与标志框相交不能证明遮挡。建议后续设施台账+分割/多帧，本版不作自动结论 |
| 抛洒物/遗留物 | 已接两种限定类别模型，并可对用户 ROI 内目标提示“疑似道路异物”。不包括任意未知物，也不能证明物体从车上抛出。COCO 中少数已知物也可用于规则试验 |
| 车辆类型 | 已有 COCO，新增 BDD100K 对照。类别随模型显示，不把普通卡车自动称为渣土车/罐车 |
| 车牌识别 | 本版定位+拍照 OCR，工程接入成本较低；真实中文牌号、侧角、夜间等需用户验证 |
| 逆行 | 新增固定机位 ROI 的反向轨迹提示；先固定手机并指定期望方向。移动巡检相机运动会使规则失效，提示不等同交通违法判定 |
| 应急车道停车 | 新增 ROI 停留提示，区域与时长由用户设置；不自动识别应急车道、禁停条件或特殊豁免 |
| 实线变道 | 新增虚拟线跨越提示。虚拟线不等于实际实线；要做完整功能还需车道线检测及几何关联，可参考 [UFLDv2](https://github.com/cfzd/Ultra-Fast-Lane-Detection-v2)，其输出/预处理不同于现有 YOLO，未接入 |
| 交通事故 | 找到 [YOLO11x 事故/车辆模型](https://huggingface.co/Enos-123/traffic-accident-detection-yolo11x) 的现成权重，但体积/计算开销较大，单帧事故外观不证明事故发生。本版未接，适合后续固定摄像头时序验证 |
| 超速、超高、车距和位置 | GPS 是手机自身位置/速度，不是目标车速度。真实米、km/h、车高需相机标定/路面映射或额外传感器；本版仅归一化检测框、粗轨迹和手机定位，未输出伪物理量 |
| 救护车、渣土车、罐车等 | 本次核查的一些项目仅有训练代码/空模型仓库，未核验到适合本工程直接分发的完整轻量专用权重。不能用普通 car/truck 替代专用类别，留待专项模型 |

固定机位规则是自有轻量类别一致的 IoU/中心点关联，不是 ByteTrack。若后续需要更稳健遮挡跟踪，可以复用 [ByteTrack 官方 NCNN/C++ 部署](https://github.com/FoundationVision/ByteTrack/tree/main/deploy/ncnn/cpp)，但它也不能自动解决相机运动、真实道路语义或标定。

## 测试方法与边界

在“实验”或模型菜单逐个切换，先 CPU/320，再试480/640和系统 Vulkan。交通标志可先对屏幕/打印图测试入口，再到真实道路验证；屏幕识别成功不代表实景精度。车牌模式先看到框再拍照，到记录查看号码候选。垃圾模式可先测试瓶、杯、纸盒、袋子。

规则只在固定手机时启用，设置 ROI、行进方向、停留时长；移动前关闭。切模型/镜头、离开相机或进入后台会自动关闭规则。实验室可一键恢复 COCO Nano/CPU/320/640×480并关闭全部规则。可选1280×720采集档，失败或无首帧回落到640×480；实际设备支持与小目标收益待测。

已做的是转换数值一致性、原生加载/推理、规则序列、合成 OCR 及照片/JSON 契约检查；这些不是公开测试集精度，也不是小米13性能/相机/GNSS验收。模型自报指标来自不同数据集，不能直接横向排名。新增能力以实验项交付，依据真机反馈逐项保留或删除。
