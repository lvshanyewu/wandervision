## 叙述调整

项目定位为课程演示：手机边缘感知、结构化数据汇集、人工复核与可视化归纳。展示仪表盘保留校园地图和循环模拟预览，后台数据工作台承担数据整理。避免描述为生产级自动道路治理、已验证的多手机集群或高精度道路检测系统。

数据流程：Android拍照与本地YOLO → JPEG及完整JSON一键上传 → 轻量Python API → SQLite统一台账 → 人工查看/复核/标签/备注 → 筛选CSV/JSON → HTML可视化报告与打印PDF。SIM/TEST/REAL清楚标注；一张采集照片对应一条台账，同帧目标作为目标数组。模型原始标签/class_id不按另一模型的类别表重解释。无GPS保持未定位。

## 可引用实现与证据

`web/data_center.py`实现台账、复核日志、聚合、导出和HTML报告；`web/server.py`集成原接口；`web/static/admin/`实现后台，前台仍为原生HTML/CSS/JS。无需前端构建及新的运行依赖。台账最多3000条/30天，照片7天/50张/96MiB，清库仅作用本Demo。审核是课程交互流程，没有生产权限系统。

Android3.4.1新增冻结保存的采集点与备注；完整YOLO/定位/模型/OCR/实验规则信息随照片JSON上报。Android构建、签名和模拟器验证由App对话负责，真实手机检测效果、GPS精度与稳定性需用户提供，不能用Web测试替代。Web58项自动测试不代表58种真实道路场景。
